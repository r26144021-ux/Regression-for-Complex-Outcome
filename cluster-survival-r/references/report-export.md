# 分析後的 QMD／HTML 報告

## 何時詢問
先完成對話中的結果、診斷與限制，再自然問：「需要我把這次分析整理成可重現的 QMD 與可直接閱讀的 HTML 報告嗎？」使用者已要求檔案就直接製作，不再確認；若拒絕則結束，不自動建立。資料／診斷不完整時可產生已清楚標示限制的報告，不補造數值。

## 內容
1. 研究目的與主要比較／估計目標。
2. 資料來源、每列意義、重複測量／群集結構、列數及獨立群數。
3. 變數表：名稱、角色、單位、類別／事件編碼、參考組；缺失與資料處理紀錄。
4. 建模前探索：保留與問題、選模或結果解釋有關的摘要／圖表、實際發現與對設定的影響，並顯示對應 R 程式；按 `eda.md` 選取，不強制同一套圖表。
5. 模型選擇理由、公式、family/link、隨機／相關結構、估計與推論方法。
6. 結果表、圖、效果量與區間、模型適用且實際執行的檢定及解釋。無適當 p 值的方法不強行補 p。
7. 診斷與限制：Cox 的 Schoenfeld 殘差檢定／圖；混合模型的收斂等；GEE 的群數與少樣本處理。未執行項目如實標示。
8. 結論、程式、sessionInfo 與來源。

## 製作與驗證
報告預設同時顯示 R 程式碼與結果：execute.echo:true、format.html.code-fold:false，可啟用 code-tools:true 方便檢視原始碼。資料讀取、前處理、模型、檢定與繪圖程式均保留；不能只顯示結果。只有使用者另有要求時才折疊或隱藏程式碼。
QMD 使用 Quarto R/knitr 引擎、UTF-8、HTML embed-resources:true。可參考 assets/analysis-report.qmd，替換所有提示內容並填入本次真實分析程式，不把空白範本稱為完成報告。用相對路徑；報告需資料檔時先確認分享範圍，不擅自打包敏感資料，說明如何取得或設定資料路徑。內建資料可直接由套件載入。

先檢查 Quarto、R、knitr／rmarkdown 與模型套件。以 `quarto render analysis-report.qmd --to html` 執行並檢查成功狀態、表格、公式、中文字及圖片。不能因 QMD 寫好就稱 HTML 已生成；不可把錯誤 chunk 隱藏成成功。若 Quarto 不可用，先交 QMD 並說明尚未渲染；若另外以既有 R 結果產生 HTML，標明其為靜態報告，不假稱經 Quarto 重新執行驗證。

渲染可能重跑模型。使用固定種子（如需模擬）、記錄套件版本，核對與對話結果是否同資料同設定。不得只把先前數字硬寫在文字中而沒有計算來源。輸出到使用者指定或本次 deliverables 目錄；已有同名檔案先用不同檔名／版本保留。

官方文件：https://quarto.org/docs/computations/r.html 、https://quarto.org/docs/output-formats/html-basics.html

診斷圖產生後必須實際檢視並解釋「這張圖」的趨勢、偏離與不確定性，不能只寫通用讀圖指令或「需搭配圖」。將圖形發現與檢定結果整合進結論；未完成的敏感度分析另行說明，不假稱已做。二元 GEE 殘差不能直接套常態 QQ 圖的 LMM 判讀。

## 診斷與結論的表達
先寫目前證據支持的整體判斷，再寫具體圖形偏離或資料限制。若診斷整體尚可且無明確重大違反，可說「可作為初步分析模型」，搭配實際發現；若有明顯違反、未收斂或其他實質問題，據實指出並處理，不自動套用「合適」。
檢定未拒絕時，使用「未發現足夠證據顯示……」等精確措辭即可，不在每項結果後重複加「不等於證明成立」「不能確定」。圖中明確的上升趨勢、尾端偏離、少群推論或未調整混雜等有資訊量的限制仍需保留。進一步分析依需要提出，不一律在所有結論後列長串警語。
LMM 只有 QQ 圖時稱「常態性圖形檢查」，不寫「常態性檢定通過」。區分本次實際執行的檢定／診斷與建議的未執行敏感度分析。

## 摘要與模型專屬圖表
製作報告前讀 `report-visuals.md`：頂部摘要與選模理由，以及適用的 KM／At-risk、HR 森林圖、C-index、GEE 邊際預測、LMM 數學式與變異分解。依目的與可用資料選取，不把所有圖表設為每次必做。

## UTF-8 與中文輸出檢查
QMD 與 R 來源檔以 UTF-8 儲存；在每份報告首個 R chunk、任何中文表格輸出前，使用範本中的 utf8-setup 確認 `l10n_info()[["UTF-8"]]`。不依賴先前工作階段、外部 Rprofile 或系統 code page 65001；R 的 LC_CTYPE 仍可能是 C。若非 UTF-8，在本次 R 工作階段嘗試可用的 UTF-8 語系，檢查回傳結果；不可變更整台電腦的語系設定。若無可用語系或中文輸出測試失敗，停止產生完成報告並說明原因。記錄最終 `Sys.getlocale("LC_CTYPE")` 與 sessionInfo。

HTML 產生後，搜尋原始 HTML 與必要的中間表格輸出是否含字面 `<U+XXXX>` 或 `&lt;U+XXXX&gt;`（排除僅在顯示程式碼中出現的測試字串），並實際檢視至少一個動態中文表格與產生的圖中文字。圖中文字也可能因字型缺字而異常，需另選支援中文的字型，不能只靠 UTF-8 保證正常。發現異常時修正語系／來源編碼／字型後重新執行，再核對；不要僅替換最後 HTML 的代碼而留下不可重現的 QMD。檢查受影響欄位的標籤與數值是否仍正確對應。
