# 群集角色、選模澄清與範圍界線

## 先辨認群集，不等使用者說專有名詞
使用者提到抽樣群集、醫院、班級、家庭或同一人多次測量時，主動確認同群多列與層級，評估群內相關；不要求先說「相關性」「GLMM」或「GEE」。只有欄名 cluster 也不足以證明有群集：它可能是分群演算法的標籤、分層變數或一般分類。先確認形成方式、每列意義、群數、群大小與對象識別。

## 群集可能有三種角色
1. **相關性來源**：同醫院／同班／同人觀測彼此可能相關。
2. **要比較的具名組別**：特定醫院 A 相對 B，或使用者定義的類別。
3. **兩者兼具**：有具體比較，同時有群內相關，需要分別處理。

使用者說「比較不同 cluster 的風險／差異」只是研究目的線索，不是指定固定效果、也不是授權一般 logistic。

## 依用途澄清，先問開放問題再提供選項
可問：「這個 cluster 是怎麼形成的？你比較群集後想回答什麼或做什麼決策？」若仍不清楚，再用具體例子協助：
- 想了解群集間變異、條件於群集效果的關聯或個別預測：評估混合效應。二元結果可提出 binomial-logit GLMM，例如 `diabetes ~ age + gender + (1 | cluster_id)`。群數、事件分布與量測結構需支持估計。
- 想知道整體族群中年齡／性別與結果的平均關聯，群集主要用來處理相關性：評估 GEE。
- 想比較特定具名群集與參考群：先說明固定效果比較與隨機效果估計的差別。隨機截距與收縮估計，不是每個具名群對參考群的固定 OR；一般 logistic 加群集虛擬變數也不會自動提供所需的穩健推論。若需要的方法超出本 Skill，停止建模並說明原因。
- 研究「年齡的整體關聯」也不一定只能用 GEE；混合模型同樣可估固定效果。說清估計目標、假設與資料可行性，再確認候選模型，避免把兩句話機械對應到唯一模型。

資訊足夠時先回述：「我理解 cluster_id 是醫院，院內有多位病人；你關心醫院間差異及調整年齡、性別後的關聯。建議先用二元 GLMM，讓醫院有隨機截距。使用這組設定可以嗎？」這是可修正的分析方案，不是引述內部規則。

使用者回答「比較群集」只更新研究目的；回答「要放年齡」只更新共變數。兩者都不等於同意變更模型。若用途仍有兩種合理解讀，暫停相依建模，先用一個問題釐清。

## 抽樣群集
另外確認抽樣權重、分層與 PSU，以及目標是樣本內關聯或複雜抽樣母體推論。若需要設計式估計（例如 survey 的設計型 logistic），明確說本 Skill 的基本 GLMM／GEE 不會自動取代抽樣設計，停止並建議適用方法。沒有權重也不能假設一定為簡單隨機抽樣。若資料結構與目的允許使用範圍內模型作樣本內探索，先明確說明不同目標與限制，再取得對該模型的確認；不能把探索標籤當作任意改用範圍外方法的理由。

## 模型範圍核對
已指定 GLMM 時保留此要求；若缺少可估計的群集／隨機效果，詢問後仍不支持 GLMM，就說：「目前資料可能較適合一般 logistic，超出這個 Skill 的分析範圍，因此這裡先不繼續建模。」可簡述候選方法及理由，不執行範圍外模型、輸出其估計結果或為其產生分析報告。不要求再加一句「相關性」來解鎖 GLMM，也不為滿足名稱硬造 id。

如果 GLMM 不收斂或 singular，先檢查資料及既定模型，必要時提出範圍內的合理修正，不能自動刪掉隨機效果改跑一般 logistic。套件在內部用 glm 初始化不算改模型；另行把普通 glm 的結果作主分析則算。
